# Contributing to Aether-Stream

Aether-Stream is a C++20 ultra-low-latency lock-free asynchronous message broker library under active development. The repository is complete through Phase 11: local library APIs, examples, CLI tools, metrics, CI verification, sanitizer configuration, clang-tidy integration, benchmark smoke checks, and CMake package install/export support.

The project is still not production-ready. Do not add unsupported latency claims, production-readiness claims, or fake benchmark numbers.

## Local prerequisites

- CMake 3.20 or newer.
- Ninja.
- A C++20 compiler such as Clang, GCC, or AppleClang.
- clang-format for formatting checks.
- clang-tidy is optional locally, but required for the CI static-analysis job.

## Build and test locally

```sh
cmake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DAETHER_BUILD_TESTS=ON \
  -DAETHER_BUILD_EXAMPLES=ON \
  -DAETHER_BUILD_TOOLS=ON \
  -DAETHER_BUILD_APPS=ON
cmake --build build/debug
ctest --test-dir build/debug --output-on-failure
```

## Formatting

Format all supported C and C++ files:

```sh
./scripts/format_all.sh
```

Check formatting without modifying files:

```sh
./scripts/format_all.sh --check
```

## Sanitizers

AddressSanitizer and UndefinedBehaviorSanitizer can be enabled together:

```sh
cmake -S . -B build/asan -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DAETHER_BUILD_TESTS=ON \
  -DAETHER_ENABLE_ASAN=ON \
  -DAETHER_ENABLE_UBSAN=ON
cmake --build build/asan
ctest --test-dir build/asan --output-on-failure
```

ThreadSanitizer must be run separately from AddressSanitizer:

```sh
cmake -S . -B build/tsan -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DAETHER_BUILD_TESTS=ON \
  -DAETHER_ENABLE_TSAN=ON
cmake --build build/tsan
ctest --test-dir build/tsan --output-on-failure
```

## clang-tidy

clang-tidy is disabled by default. Enable it explicitly when you want CMake builds to run static analysis:

```sh
cmake -S . -B build/tidy -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DAETHER_BUILD_TESTS=ON \
  -DAETHER_BUILD_EXAMPLES=ON \
  -DAETHER_BUILD_TOOLS=ON \
  -DAETHER_BUILD_APPS=ON \
  -DAETHER_ENABLE_CLANG_TIDY=ON
cmake --build build/tidy
```

## Benchmark smoke checks

Benchmark smoke checks are for build/runtime validation only. They are not official performance results:

```sh
cmake -S . -B build/bench-smoke -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DAETHER_BUILD_TESTS=ON \
  -DAETHER_BUILD_EXAMPLES=ON \
  -DAETHER_BUILD_TOOLS=ON \
  -DAETHER_BUILD_APPS=ON \
  -DAETHER_BUILD_BENCHMARKS=ON
cmake --build build/bench-smoke
ctest --test-dir build/bench-smoke --output-on-failure
./build/bench-smoke/benchmarks/bench_spsc_throughput --benchmark_min_time=0.01s
./build/bench-smoke/benchmarks/bench_spsc_latency --benchmark_min_time=0.01s
./build/bench-smoke/benchmarks/bench_payload_sizes --benchmark_min_time=0.01s
./build/bench-smoke/benchmarks/bench_broker_end_to_end --benchmark_min_time=0.01s
```

Only publish benchmark numbers when they are generated by `scripts/run_benchmarks.sh` with environment details and raw outputs preserved.

## Pull request checklist

- Keep changes focused on the requested phase or issue.
- Run formatting checks and relevant tests locally.
- Use sanitizers for code that changes concurrency, memory, WAL, mmap, or broker behavior.
- Keep benchmark output honest; do not paste unsupported latency or throughput numbers.
- Update documentation when behavior, commands, or limitations change.
- Avoid new external dependencies unless the active phase explicitly asks for them.

## Commit style examples

- `ci: add build and test workflow`
- `build: add install/export rules`
- `docs: add release checklist`
