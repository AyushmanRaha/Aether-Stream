# Contributing to Aether-Stream

Aether-Stream is a local C++20 systems project with bounded messaging, persistence, diagnostics, tests, benchmarks, and CMake package support. The project is not production-ready. Contributions should stay precise, scoped, and honest about limitations.

## Local prerequisites

- CMake 3.20 or newer.
- Ninja.
- A C++20 compiler such as Clang, GCC, or AppleClang.
- clang-format for formatting checks.
- clang-tidy for optional local static analysis.

## Build and test locally

```sh
cmake -S . -B build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug   -DAETHER_BUILD_TESTS=ON   -DAETHER_BUILD_EXAMPLES=ON   -DAETHER_BUILD_TOOLS=ON   -DAETHER_BUILD_APPS=ON
cmake --build build/debug
ctest --test-dir build/debug --output-on-failure
```

## Formatting

```sh
./scripts/format_all.sh
./scripts/format_all.sh --check
```

## Sanitizers

```sh
cmake -S . -B build/asan -G Ninja -DCMAKE_BUILD_TYPE=Debug   -DAETHER_BUILD_TESTS=ON   -DAETHER_ENABLE_ASAN=ON   -DAETHER_ENABLE_UBSAN=ON
cmake --build build/asan
ctest --test-dir build/asan --output-on-failure
```

```sh
cmake -S . -B build/tsan -G Ninja -DCMAKE_BUILD_TYPE=Debug   -DAETHER_BUILD_TESTS=ON   -DAETHER_ENABLE_TSAN=ON
cmake --build build/tsan
ctest --test-dir build/tsan --output-on-failure
```

## clang-tidy

## Benchmark smoke checks

Benchmark smoke checks validate that benchmark executables build and run briefly. They are not official performance results.

```sh
cmake -S . -B build/bench-smoke -G Ninja -DCMAKE_BUILD_TYPE=Release   -DAETHER_BUILD_TESTS=ON   -DAETHER_BUILD_EXAMPLES=ON   -DAETHER_BUILD_TOOLS=ON   -DAETHER_BUILD_APPS=ON   -DAETHER_BUILD_BENCHMARKS=ON
cmake --build build/bench-smoke
ctest --test-dir build/bench-smoke --output-on-failure
./build/bench-smoke/benchmarks/bench_spsc_throughput --benchmark_min_time=0.01s
```

Only publish benchmark numbers generated by `scripts/run_benchmarks.sh` with raw output and environment details preserved.

## Pull request checklist

- Keep changes focused on the requested issue.
- Run formatting checks and relevant tests locally.
- Use sanitizers for changes touching concurrency, memory lifetime, WAL, mmap, or broker behavior.
- Keep benchmark output honest; do not add unsupported latency or throughput numbers.
- Update documentation when behavior, commands, filenames, or limitations change.
- Avoid new external dependencies unless explicitly requested and justified.

## Commit style examples

- `ci: add build and test workflow`
- `build: add install/export rules`
- `docs: update benchmark methodology`
